# SEO standards

Search engines and share previews read the HTML that the server sends. `docs/content.md` decides **what** each page says and what its metadata is. This file decides **how** that is delivered. `scripts/seo_check.py` checks the result on the running site.

## Rendering

- Public pages are rendered on the server or at build time (SSG, SSR, ISR). The title, the meta tags, the canonical link, Open Graph, JSON-LD and the main content must be in the first HTML response. Messenger and social preview bots do not run JavaScript, and search engines render it late, if at all.
- A client-only SPA is fine behind sign-in. It is not fine for public pages.
- Every route returns the right status: 200 for a page, 301 for a moved page, 404 for a missing one (a real 404 status, not a 200 page that says "not found"), and 410 for one removed for good.

## Every public page

Values come from `docs/content.md`. Keep them in one typed place per page, never as literal strings scattered through components.

- `<html lang="…">`, `<meta charset="utf-8">` and `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- `<title>`: unique and specific. It states the page's key message in the words people search for, in about 60 characters before it gets cut, with the brand at the end (`Page — Brand`). No keyword lists.
- `<meta name="description">`: unique, and it summarizes this page. There is no hard limit, but about 150 characters show. No keyword lists. Google may rewrite it; a good one is still the default.
- `<link rel="canonical" href="https://…">`: absolute, on the canonical host, and pointing at the page itself for normal pages. URLs with tracking or sorting parameters point at the clean URL.
- Exactly one `<h1>`, which carries the key message. Headings go in order without skipped levels.
- Open Graph: `og:title`, `og:description`, `og:type` (`website`, `article`, `product`…), `og:url` (equal to the canonical), `og:image`, `og:image:alt`, `og:site_name` and `og:locale`.
- `og:image`: an absolute HTTPS URL, 1200×630, PNG or JPEG, under 1 MB, with the text kept away from the edges, which some apps crop.
- Twitter/X: `twitter:card` set to `summary_large_image`. For everything else it falls back to Open Graph.
- Structured data as JSON-LD, as listed in `docs/content.md`: `Organization` and `WebSite` on the home page, `BreadcrumbList` on nested pages, and the page's own type (`Article`, `Product`, `FAQPage`, `Event`, `LocalBusiness`…). Mark up only what is visible on the page. Validate it with Google's Rich Results Test before release.
- Images have a meaningful `alt` and explicit width and height. The image above the fold is not lazy-loaded.
- Links are real `<a href>` elements with descriptive text, and navigation works without JavaScript.

## OG images

The designer provides an OG template in the chosen design (`docs/design/og-template.html`). Use one static image per page type, or generate one per page at build time with the framework's tool (`next/og`, satori, an Astro endpoint). A screenshot of the hero is not an OG image.

## Site-wide

- **One canonical host.** Redirect http to https and www to non-www (or the reverse) with a 301. Pick one trailing-slash policy and enforce it with a redirect.
- **robots.txt** in production, generated by the app or served by the proxy:
  ```
  User-agent: *
  Allow: /

  Sitemap: https://example.com/sitemap.xml
  ```
  All crawlers, AI crawlers included, are allowed by default. Add a `Disallow` only for private areas (`/admin`, `/api`) when `docs/content.md` asks for it. robots.txt controls crawling, not indexing. To keep a page out of search, use `noindex`, and do not also block that page in robots.txt, or crawlers never see the `noindex`. Do not create `llms.txt` unless the user asks.
- **sitemap.xml**: only canonical, indexable URLs that return 200, absolute and on the canonical host. Generate it from the routes and the content, never by hand. Set `lastmod` only when it is real (the content's last change), never to "now" on every build. Leave out `priority` and `changefreq`, which Google ignores. Over 50,000 URLs or 50 MB, split it with a sitemap index.
- **Multilingual sites**: a separate URL per locale (`/en/…`), and `hreflang` alternates for every locale, including the page itself and `x-default`.
- **Pages behind sign-in** and utility pages (search results, cart, "thank you"): `noindex`, and not in the sitemap.
- **Staging and preview environments**: `X-Robots-Tag: noindex, nofollow` on every response, sent by the proxy role and switched on per inventory (see `web-pipeline:ansible-conventions`), or HTTP basic auth. Production never sends it.
- **Moved URLs**: a 301 to the new URL, updated internal links and sitemap, and a row in the redirect table of `docs/content.md`.
- **Icons**: `favicon.ico`, an SVG icon, a 180×180 `apple-touch-icon`, and a web manifest with the site's name.

## Reuse first

Use the framework's own tools before writing any: Next.js `metadata` and `generateMetadata`, `app/robots.ts`, `app/sitemap.ts` and `opengraph-image`; Astro's `@astrojs/sitemap` and a shared head in the layout; Nuxt's `useSeoMeta` and `@nuxtjs/sitemap`; SvelteKit's `<svelte:head>` and a `sitemap.xml` endpoint; Django's `django.contrib.sitemaps`.

## Performance

Core Web Vitals at the 75th percentile on mobile: LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1. Preload the LCP image and the display font, use `font-display: swap` with a metric-matched fallback, and keep late banners from shifting the layout.

## The gate: seo_check.py

`web-pipeline:init` copies the checker to `scripts/seo_check.py` and adds a `make seo` target. It needs the site running, so it is not part of `make check`. It reads every page the way bots do, without JavaScript: it follows robots.txt to the sitemap, checks every listed page, and checks that a missing URL returns 404.

```bash
make seo                                                              # local, against the dev server
python3 scripts/seo_check.py http://localhost:3000 --site-url https://example.com
python3 scripts/seo_check.py https://staging.example.com --expect noindex
```

- `--expect index` (the default) is for production and the local check of a public site. `--expect noindex` is for staging and for private apps that must stay out of search.
- Errors must be fixed. Warnings (lengths, image size, a missing `twitter:card`, several `<h1>`) are judged by the design critic.
- If a rule does not apply to this project, skip it with `--ignore <rule>` in the `seo` target, with a comment explaining why.
