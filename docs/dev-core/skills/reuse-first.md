# reuse-first

Протокол, который выполняется перед написанием любого нового модуля, функции, хелпера, хука или компонента. Его цель — не писать то, что уже есть в проекте, в языке или в поддерживаемой библиотеке.

|---|---|

| Автовызов | Да, когда Claude собирается реализовать новую функциональность |

## Когда срабатывает

> Protocol to run before writing any new module, function, helper or component - check the project, the standard library/framework and maintained libraries before writing custom code. Use whenever about to implement new functionality.

## Четыре вопроса по порядку

Ответы ищутся по порядку, остановка на первом «да». Протокол действует на протяжении всей задачи, а не только в её начале.

### 1. Есть ли это уже в проекте?

- Искать по смыслу, а не только по имени: хелпер slugify может называться `toUrlPart`.
- Grep по глаголу и существительному (`format.*date`, `retry`, `paginate`, `debounce`) и по ключевой библиотеке, через которую это строилось бы.
- Обычные места: `utils/`, `lib/`, `common/`, `shared/`, `core/`, `helpers/`, базовые классы, middleware, существующие хуки и компоненты, дизайн-система.
- Если есть что-то близкое, **расширить или обобщить** его, а не писать соседний вариант. Если расширение ухудшит код, объяснить это в reuse-заметке.

### 2. Умеет ли это язык или фреймворк?

Стандартная библиотека, встроенные возможности фреймворка, ORM, платформенные API. Например: `Intl.DateTimeFormat`, `URLSearchParams`, `structuredClone`, `itertools`, `functools.cache`, `pathlib`, формы и валидаторы Django, зависимости FastAPI, route handlers Next.js, нативные `<dialog>`, валидация форм и `:has()` в браузере.

### 3. Есть ли поддерживаемая библиотека?

Актуальная документация берётся через [Context7](../context7.md) (`resolve-library-id`, затем `get-library-docs`), чтобы использовать текущий API, а не вспоминаемый. Библиотека принимается, только если выполнены все условия:

- релиз или существенный коммит примерно за последние 12 месяцев, на issues отвечают;
- совместимая лицензия (MIT, BSD, Apache-2.0, ISC, MPL-2.0). GPL и AGPL обсуждаются с вами;
- нет открытых advisories уровня high или critical (`osv-scanner`, `npm audit` / `pip-audit`);
- разумный размер: не фреймворк ради одной функции, транзитивные зависимости проверены.

Библиотека, которая уже есть в зависимостях проекта, предпочтительнее новой, даже если новая чуть лучше.

### 4. Только теперь писать

Самое маленькое работающее решение (KISS) в том месте, где его будет искать следующий человек.

## Баланс DRY и KISS

- **Правило трёх**: один раз продублировать можно, абстрагировать на третьем повторе. Два похожих блока — ещё не паттерн.
- Не добавлять зависимость ради примерно 10 очевидных строк без краевых случаев: у зависимостей есть цена обновлений, безопасности и цепочки поставок. Добавлять зависимость для всего, где есть реальные краевые случаи: даты и часовые пояса, криптография, авторизация, парсинг, валидация, ретраи с backoff, CSV, Markdown, i18n, санитизация HTML.
- Никогда не писать самим криптографию, хэширование паролей, сессии и авторизацию, санитизацию HTML и экранирование SQL.

## Reuse-заметка

Для каждого нового модуля в отчёте (не в коде) оставляется строка:

```text
reuse: <module> - project: none (searched utils/, lib/) · stdlib: n/a · library: date-fns (already a dep) → used
```

Ревьюеры проверяют эти заметки. Отсутствующая заметка или самописная версия того, что нашлось бы на шагах 1–3, — находка уровня **major**.
