Правила устройства плагинов в этом репозитории. Короткая версия для Claude лежит в `CLAUDE.md` в корне.

## Структура репозитория

```text
.claude-plugin/marketplace.json    # каталог marketplace nikiquark-ai-plugins
plugins/
  dev-core/
    .claude-plugin/plugin.json
    .mcp.json
    bin/                            # исполняемые файлы для инструмента Bash
    hooks/hooks.json
    scripts/                        # скрипты хуков
    skills/<name>/SKILL.md
  web-pipeline/
    .claude-plugin/plugin.json      # "dependencies": ["dev-core"]
    .mcp.json
    agents/<name>.md
    hooks/hooks.json
    scripts/
    shared/                         # фрагменты, которые читают несколько скиллов
    skills/<name>/SKILL.md (+ references/)
    templates/
src/content/docs/                  # этот сайт
astro.config.mjs                    # конфиг сайта и сайдбар
scripts/check-docs.py
```

## Общее и доменное

- Общая логика живёт в `dev-core`. Доменные плагины объявляют `"dependencies": ["dev-core"]` и обращаются к общим скиллам по полному имени (`dev-core:review-loop`).
- **Скиллы между плагинами не копируются.** Если доменному плагину нужен общий механизм, он переносится в `dev-core`.
- Фрагменты, общие для нескольких скиллов одного плагина, лежат в `shared/` и читаются через `${CLAUDE_PLUGIN_ROOT}/shared/…` (пример — `delivery-phases.md`).

## Хуки

- Хуки плагина срабатывают **во всех проектах**. Поэтому каждый доменный плагин включает свои хуки только при наличии файла-маркера в проекте: `.claude/<plugin>.json`.
- Исключение допустимо только для хуков, которые ничего не запускают, а лишь спрашивают или запрещают (как `guard-bash.sh`).
- Хук должен быть быстрым и не зацикливаться: проверять, изменилось ли что-то, и ограничивать число блокировок.

## Агенты

- Плагинные агенты игнорируют `permissionMode`, `hooks` и `mcpServers` во frontmatter.
- Чистый ревьюер, который никогда не пишет файлы (например, `web-pipeline:code-reviewer`), делается агентом только на чтение через `disallowedTools: Write, Edit, NotebookEdit, Agent`.
- Агент, который в одном режиме ревьюит, а в другом пишет свои файлы (например, `idea-pipeline:red-team` и `idea-pipeline:fact-checker`), получает список `tools`, а запрет на правки в режиме ревью задаётся в тексте агента.
- Модель и effort задаются во frontmatter под задачу агента. Навыки предзагружаются через `skills:`, а тело агента всё равно просит загрузить их инструментом `Skill`, если их нет в контексте.

## Пути

- `${CLAUDE_PLUGIN_ROOT}` подставляется в текст скиллов и агентов и экспортируется в хуки, но **его нет** в окружении инструмента Bash. Исполняемые файлы, которые запускает Claude, кладутся в `bin/` плагина: они попадают в PATH.
- Установленные плагины лежат в отдельных каталогах кэша для каждой версии. **Никогда не ссылайтесь на соседний плагин относительным путём.**

## Состояние

- Каждый пайплайн хранит возобновляемое состояние в `.claude/state/pipeline.json` проекта. По этому файлу работает context-guard из `dev-core`.
- Оркестратор должен возобновляться из файла состояния и документов, чтобы `/clear` и повторный запуск команды ничего не теряли.

## Язык

- Тела скиллов и агентов пишутся на английском.
- Пользовательская документация (README и этот сайт) пишется на русском. Идентификаторы (имена скиллов, флаги, поля JSON) остаются как есть.
